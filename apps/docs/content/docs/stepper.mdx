The HBD `Stepper` is a native `<input type="number">` flanked by decrement (−)
and increment (+) buttons, wrapped in the shared `.hbd-field` chrome (label,
hint, error). The input is the sole Tab stop; keyboard users adjust with the
arrow keys (`PageUp`/`PageDown` for ±10·step, `Home`/`End` for the bounds),
while the buttons are mouse/touch targets.

## Thin

`thin` collapses the field to its intrinsic width instead of stretching to fill
its column — for table cells, inline forms, and anywhere a full-width stepper is
too much. Both step buttons and the value field narrow accordingly.

## Step & bounds

`step` controls the increment (and is used to round away float drift), while
`min`/`max` clamp the value and disable the matching button at each boundary.

<Tabs items={["Preview", "Code"]}>
  <Tab value="Preview">
    <Preview>
      <StepperStepDemo />
    </Preview>
  </Tab>
  <Tab value="Code">
    ```tsx
    <Stepper
      label="Rudder trim"
      defaultValue="0"
      min={-1}
      max={1}
      step={0.5}
      hint="Use ± or the arrow keys to adjust in 0.5 steps."
    />
    ```
  </Tab>
</Tabs>

## States

A non-empty `error` sets `aria-invalid` and shows the error message (hiding the
`hint`). `disabled` greys out the input and both buttons.

## Controlled

Pass `value` and `onValueChange` to own the state in React. `onValueChange`
fires only on commit (button, arrow key, or blur) — not on every keystroke.

<Tabs items={['Preview', 'Code']}>
  <Tab value="Preview">
    <Preview>

    </Preview>
  </Tab>
  <Tab value="Code">
    ```tsx
    const [value, setValue] = React.useState('3');

    <Stepper
      label="Gold doubloons"
      value={value}
      onValueChange={setValue}
      min={0}
      max={20}
      required
    />
    ```
