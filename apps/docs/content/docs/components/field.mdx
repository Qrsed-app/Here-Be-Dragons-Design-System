## Installation

```bash
npx shadcn@latest add @hbd/field
```

The `@hbd` namespace needs a one-time `registries` entry in `components.json` — see
[Installation](/docs/installation). Or add it by URL, no configuration needed:

```bash
npx shadcn@latest add http://localhost:3001/r/field.json
```

## Usage

```tsx
import {
  Field,
  FieldContent,
  FieldDescription,
  FieldError,
  FieldGroup,
  FieldLabel,
  FieldLegend,
  FieldSeparator,
  FieldSet,
  FieldTitle,
} from "@/components/ui/field";
```

```tsx
<FieldSet>
  <FieldLegend>Profile</FieldLegend>
  <FieldDescription>This appears on invoices and emails.</FieldDescription>
  <FieldGroup>
    <Field>
      <FieldLabel htmlFor="name">Full name</FieldLabel>
      <Input id="name" autoComplete="off" placeholder="Evil Rabbit" />
      <FieldDescription>This appears on invoices and emails.</FieldDescription>
    </Field>
    <Field>
      <FieldLabel htmlFor="username">Username</FieldLabel>
      <Input id="username" autoComplete="off" aria-invalid />
      <FieldError>Choose another username.</FieldError>
    </Field>
  </FieldGroup>
</FieldSet>
```

A vertical `Field` keeps the Here Be Dragons 4px rhythm between label, control and messages
(8px when it holds an [Input OTP](/docs/components/input-otp)).

### Validation and Errors

`data-invalid` on `Field` turns the label blood-red; `aria-invalid` on the control draws the error
border. `FieldError` takes children, or an `errors` array (for example from react-hook-form) and
lists every unique message.

<Tabs items={["Preview", "Code"]}>
  <Tab value="Preview">
    <Preview>
      <div className="flex w-full max-w-sm flex-col gap-6">
        <Field data-invalid>
          <FieldLabel htmlFor="field-demo-email">Email</FieldLabel>
          <Input id="field-demo-email" type="email" aria-invalid defaultValue="dragon@example" />
          <FieldError>That email is already taken.</FieldError>
        </Field>
        <Field data-invalid>
          <FieldLabel htmlFor="field-demo-rune">Rune</FieldLabel>
          <Input id="field-demo-rune" aria-invalid />
          <FieldError
            errors={[
              { message: "A rune is required." },
              { message: "Runes are carved, not typed." },
            ]}
          />
        </Field>
      </div>
    </Preview>
  </Tab>
  <Tab value="Code">
    ```tsx
    <Field data-invalid>
      <FieldLabel htmlFor="email">Email</FieldLabel>
      <Input id="email" type="email" aria-invalid defaultValue="dragon@example" />
      <FieldError>That email is already taken.</FieldError>
    </Field>
    <Field data-invalid>
      <FieldLabel htmlFor="rune">Rune</FieldLabel>
      <Input id="rune" aria-invalid />
    ```

### Horizontal

`orientation="horizontal"` lines the control up with its label; `FieldContent` stacks a label and
description beside it. `responsive` switches from vertical to horizontal once the surrounding
`FieldGroup` is wide enough.

<Tabs items={["Preview", "Code"]}>

    <Preview>

        <FieldGroup>
          <Field orientation="horizontal">
            <FieldContent>
              <FieldTitle>Night watch</FieldTitle>
              <FieldDescription>Who keeps the lantern lit after dusk.</FieldDescription>
            </FieldContent>
            <NativeSelect defaultValue="bosun" aria-label="Night watch">
              <NativeSelectOption value="bosun">Bosun</NativeSelectOption>

`FieldLabel` forwards to [Label](/docs/components/label). `FieldSet`, `FieldGroup`, `FieldContent`,
