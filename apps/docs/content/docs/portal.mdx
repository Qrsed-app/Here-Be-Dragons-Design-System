The HBD `Portal` renders its children into a target element elsewhere in the
document instead of inline, mirroring the legacy `hbd-portal` web component.
It is built on `ReactDOM.createPortal`, so the subtree is torn down on unmount —
when the portal disappears, its children disappear. This is the primitive that
overlay components (modals, drawers, tooltips) use to escape clipping and
stacking-context traps.

## Usage

Pass a CSS selector (or an `Element`) as `target`. The children are removed from
where they are written and mounted into that target instead. If the target can't
be resolved, it falls back to `document.body`.

## Insertion order

By default the portalled node is appended to the end of the target. Set
`prepend` to insert it at the start instead — matching the order semantics of
the original web component.

## Props

| Prop       | Type                        | Default  | Description                                                            |
| ---------- | --------------------------- | -------- | ---------------------------------------------------------------------- |
| `target`   | `string \| Element \| null` | `"body"` | CSS selector or element to render into. Falls back to `document.body`. |
| `prepend`  | `boolean`                   | `false`  | Insert at the start of the target instead of the end.                  |
| `children` | `React.ReactNode`           | —        | Content to relocate into the target.                                   |

## Install

```bash
npx shadcn@latest add http://localhost:3001/r/portal.json
```
